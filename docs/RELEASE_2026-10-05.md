### Security-header boundary
PageSpeed repeatedly reports missing CSP/HSTS/COOP/X-Frame-Options and a charset audit. The current AppDeploy tool surface exposes no response-header configuration endpoint. The existing `<meta charset="UTF-8">` is already the first metadata element in `index.html`, so the charset warning is not yet explained and should not be “fixed” by moving markup blindly. Security headers remain a platform/deployment-layer gap, not a frontend-HTML gap.

### Methodological learnings
1. DOM-width forcing is not a valid substitute for a real viewport when media-query activation depends on `window.innerWidth`.
2. A Lighthouse finding must be traced to the target geometry actually measured; increasing one dimension can leave the audit failing because width or spacing is still insufficient.
3. Runtime/browser evidence and source evidence are separate claims. A GitHub fix is not a live fix until a new deployment snapshot is published and retested.
4. Performance measurements have run-to-run variance; the mobile Performance score moved 99→94 while code changes were minor, so one rerun is not sufficient to attribute the change causally.
5. External field Core Web Vitals cannot be declared PASS from lab Lighthouse data when no field dataset exists.
